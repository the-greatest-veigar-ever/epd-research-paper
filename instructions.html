1

Create the pod

RunPod dashboard → Deploy → GPU Pod. Settings that matter:

GPU: A100 PCIe 80GB, Secure Cloud ($1.39/hr — cheapest 80GB option; needed because gpt-oss:120b alone is ~65GB)
Template: "RunPod PyTorch" (ships with CUDA + Python already set up)
Disk: at least 200GB container/volume disk — the 7 model tags total ~130GB on disk before you add the repo and checkpoints

2

Connect to the pod

Once it's running, use the "Connect" button → Web Terminal, or SSH if you'd rather use your own terminal.

3

Install & start Ollama

curl -fsSL https://ollama.com/install.sh | sh
ollama serve > ~/ollama.log 2>&1 &
# confirm it's up:
curl http://localhost:11434
4

Get the code

git clone https://github.com/the-greatest-veigar-ever/epd-research-paper.git
cd epd-research-paper
git checkout thach-23-mar-2026
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
ⓘ
run_runpod_experiment.sh is already in this branch and already executable — nothing to configure, just run it in Step 7.
5

Pull all 7 models

~130GB total — this is the slowest setup step, budget real time for it depending on the pod's network.

6

Sanity check before the full run

Confirms the GPU is visible, a fast and a slow SLM cell both work, and gpt-oss:120b actually fits in 80GB before committing 7–17 hours to it.

nvidia-smi   # should show ~80GB total

python3 -m src.ghost_agents.approach_evaluation.benchmark_evaluator \
    --approaches phi3_static deepseek_r1_1_5b_suicide \
    --benchmarks SecurityEval --seeds 42 --max-per-benchmark 3 --verbose

python3 -m src.ghost_agents.approach_evaluation.benchmark_evaluator \
    --approaches gpt_120b_oss_static --benchmarks SecurityEval \
    --seeds 42 --max-per-benchmark 1 --verbose
7

Run the full experiment, inside tmux

This runs 7–17 hours. tmux keeps it alive if the SSH/web terminal session drops — don't skip this part.

sudo apt-get install -y tmux   # skip if already installed
tmux new -s epd
./run_runpod_experiment.sh
# detach without killing it: Ctrl+B, then D
# reattach any time:
tmux attach -t epd
ⓘ
The script itself runs the 5 SLMs concurrently, then the 2 LLM baselines sequentially, and exits non-zero if an SLM run fails before starting the LLM phase. If one model errors, re-run just that model's command — checkpointing means finished (benchmark, approach) cells aren't redone.
8

Check on it anytime

tmux attach -t epd                                    # see live output
tail -f report-output/ghost_agents/run_logs/*.log     # per-model logs
nvidia-smi                                            # confirm the GPU is actually busy
9

Send the results back

Results aren't gitignored, so pushing them is the simplest handoff — they're metrics JSON, not model weights.

git checkout -b runpod-results-2026-08-20
git add report-output/
git commit -m "RunPod run: 5 SLM (parallel) + 2 LLM baselines, seeds 42/43/44"
git push origin runpod-results-2026-08-20

Then just message the branch name over — no PR needed unless you want one.

10

Pause safelyif you'll be back

tmux only protects against a dropped connection — closing the laptop or losing SSH doesn't stop the pod or its billing. Actually pausing needs RunPod's own Stop, and it's safe to do at any point: the evaluator checkpoints every 20 test cases (--save-every), so stopping mid-run loses at most a few in-flight test cases per model, never the whole run.

How: RunPod dashboard → the pod → Stop (not Terminate). Stop releases the GPU and pauses compute billing, but keeps the container disk exactly as it is — repo, venv, all 7 pulled models (~130GB), and every checkpoint JSON file already written.

⚠
Stopped isn't free: RunPod bills a stopped pod's disk at its idle storage rate, roughly double the running rate. At ~200GB that's around $1.30/day sitting stopped — trivial for a pause of a few days, worth remembering if it sits stopped for weeks.
11

Resume later

RunPod dashboard → find the stopped pod → Resume. Reconnect from the Connect button — SSH port and other connection details can change on restart, so grab fresh ones rather than reusing the old command.

The disk is exactly as left: repo, venv, and all 7 models are still there — no re-cloning, no re-pulling 130GB. Two things do need restarting, since they were processes tied to the old container session, not files on disk:

source .venv/bin/activate            # if not already active
ollama serve > ~/ollama.log 2>&1 &

tmux new -s epd
./run_runpod_experiment.sh
ⓘ
Safe to do even if some models finished before the pause and others didn't. The framework checkpoints per (benchmark, approach) pair — anything already complete prints already complete ... skipped and costs zero additional GPU time; anything partway through resumes from its last checkpoint instead of restarting.
12

Finished — shut down for goodonly after results are pushed

⚠
RunPod dashboard → the pod → Terminate. This deletes the pod and its disk entirely — repo, venv, all ~130GB of pulled models, everything. There's no resuming from a terminated pod, so only do this once Step 9's push is confirmed on GitHub. If there's any doubt, Stop instead and terminate later — the idle storage cost from Step 10 is a lot cheaper than re-downloading 130GB of models.

Cost and timing assumptions (GPU choice, the $9–24 estimate, why SLMs run concurrently and the LLMs don't) are worked through in the companion cost memo — worth a skim if something looks off during the run.

Model tags, disk footprint, and command names are read directly from approaches.py / README.md in the repo at commit time — if the branch has moved on, re-check --list-approaches before running.
